# مستودعات مديرية صحة دمشق المركزية — تطبيق سطح مكتب

**Damascus Health Directorate Central Warehouses** — نظام إدارة مستودعات صحية مركزية، نسخة سطح مكتب
**محلية بالكامل** (تعمل دون إنترنت) مبنية على Electron + React + SQLite.

> مشروع مستقل بالتوازي مع النسخة السحابية القديمة (`whsham`) — لا يتشارك معها أي كود أو بيانات.

## القرارات المعتمدة
| القرار | الاختيار |
|---|---|
| طبقة البيانات | محلية بالكامل (SQLite) — لا اعتماد على أي خدمة سحابية |
| محرّك الحزم | Electron |
| أسلوب العمل | مشروع جديد نظيف بالتوازي |
| الذكاء الاصطناعي | مستبعَد من هذه النسخة |
| المستخدمون | جهاز واحد |

## المبدأ الأمني الحاكم
> لا منطق أمني في الواجهة. كل قرار صلاحية يُتخذ في العملية الرئيسية ويُتحقق منه قبل التنفيذ، وكل عملية حساسة تُسجَّل في سجل تدقيق لا يقبل التعديل.

| المجال | التنفيذ |
|---|---|
| عزل المحتوى | `contextIsolation` · `sandbox` · `nodeIntegration: false` · CSP · منع التنقّل وفتح نوافذ |
| جسر IPC | قنوات مُعدَّدة بأسماء صريحة (لا تمرير عام) + تحقق `zod` لكل حِمل + خريطة صلاحية لكل قناة + عدم تسريب أي تفاصيل تقنية |
| المصادقة | `scrypt` بملح لكل مستخدم · مقارنة زمنية ثابتة · قفل بعد 5 محاولات (15 دقيقة) · مهلة جلسة خمول · إلزام تغيير كلمة المرور الأولى |
| الصلاحيات | 8 أدوار × 25 صلاحية في مصدر واحد · **إنكار ضمني** · حماية آخر مدير نظام من التعطيل/التخفيض · تسجيل كل رفض |
| التدقيق | سجل إضافة-فقط (منع الحذف على مستوى القاعدة) + سلسلة بصمات SHA-256 + دالة تحقق تكشف أي تعديل |
| قاعدة البيانات | قيود `CHECK`/`TRIGGER` تمنع الأرصدة السالبة · كل حركة داخل معاملة واحدة · فرض الإغلاق المالي |
| مخزون | FIFO حقيقي (الأقرب انتهاءً ثم الأقدم) · نقل يحافظ على الدفعات وتواريخ الصلاحية · تسوية جرد بفرق صريح |
| البيانات الشخصية | الرقم الوطني مشفَّر AES-256-GCM بمفتاح محلي مُقيَّد · الكشف يتطلب صلاحية ويُسجَّل في التدقيق |
| العمليات | نسخة واحدة من التطبيق (`single instance`) · نسخ احتياطي بفحص سلامة + نسخة أمان قبل الاستعادة |

## الوحدات المنفَّذة
- **التشغيل:** لوحة معلومات · مخزون وحركات (إدخال/إخراج/نقل/إتلاف/تسوية) · مسح باركود (BarcodeDetector + إدخال يدوي) · عهد شخصية (تسجيل/إرجاع/كشف رقم وطني) · تعميمات وتنبيهات.
- **البيانات:** كتالوج المواد · المستودعات · المورّدون.
- **المتابعة:** 6 تقارير جاهزة (أرصدة · حركات · تحت الحد · قرب الانتهاء · عهد مفتوحة · سجل التدقيق) مع تصدير CSV متوافق مع Excel · سجل تدقيق مع تحقق من سلامة السلسلة.
- **الإدارة:** المستخدمون والأدوار ومصفوفة الصلاحيات · النسخ الاحتياطي والاستعادة · إعدادات الجهة والإغلاق المالي.

## البنية
```
src/
  shared/      مصفوفة الأدوار والصلاحيات والثوابت (مصدر الحقيقة الوحيد)
  main/        العملية الرئيسية (Node)
    db/        schema.ts — المخطط وقواعد العمل · database.ts — الاتصال والتهيئة
    services/  crypto · audit · auth · users · catalog · inventory · custody · reports · backup · notices · settings
    ipc/       contract.ts — العقد والتحقق · register.ts — التسجيل وفحص الصلاحيات
  preload/     الجسر الآمن (contextBridge)
  renderer/    واجهة React عربية RTL: screens/ + panels/ + components/
tests/         اختبارات node:test لمنطق المخزون والتدقيق والصلاحيات
```

## التشغيل والتحقق
```bash
npm install
npm run rebuild     # إعادة بناء better-sqlite3 ليطابق إصدار Electron (مرة واحدة)
npm run dev         # تشغيل وضع التطوير
npm run verify      # فحص الأنواع + الاختبارات + البناء
npm run dist        # إنتاج مثبّت Windows (NSIS) في مجلد release/
```

عند أول تشغيل تُنشأ القاعدة في مجلد بيانات التطبيق، وتُكتب كلمة مرور المدير الأولية في
`first-run-admin-password.txt` — يجب تغييرها فور أول دخول ثم حذف الملف.

## حالة الاختبارات
`npm run test` يشغّل اختبارات على قاعدة SQLite في الذاكرة تغطي: الإدخال · ترتيب FIFO · رفض نقص الرصيد دون أثر جزئي ·
النقل مع الحفاظ على الدفعات · التسوية · سلامة سلسلة التدقيق وكشف التعديل · منع حذف السجل · مصفوفة الصلاحيات.

## ما تبقّى على خطة العمل
- ترميز الأصول والأيقونات الرسمية + ترويسة التقارير المطبوعة (A4) والملصقات.
- تشفير ملف القاعدة بالكامل (SQLCipher) — يتطلب بناءً أصليًا مخصصًا.
- سجل الحضور/الجرد السنوي المتقدم وكشوف التسليم الرسمية الموقّعة.
- التوقيع الرقمي لحزمة التثبيت إن لزم التوزيع خارج نطاق الجهة.
